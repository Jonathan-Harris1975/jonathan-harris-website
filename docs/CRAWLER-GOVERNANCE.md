# Crawler Asset Governance

## Canonical files

| Asset | Canonical path | Purpose |
|-------|---------------|---------|
| Robots | `/robots.txt` | Canonical robots directives, AI crawler allowances and sitemap pointer |
| Sitemap | `/sitemap.xml` | Canonical sitemap, referenced from robots.txt and published as the only root sitemap XML body |
| LLM index | `/llms.txt` | Human-readable crawler/retrieval index that complements normal crawlability |

## Compatibility aliases

Historical names remain compatible through direct permanent redirects or Pages Function routing. They are **not** duplicate physical sitemap bodies.

| Route | Behaviour |
| --- | --- |
| `/robot.txt` | 301 to `/robots.txt` |
| `/Sitemap.xml` | 301 to `/sitemap.xml` |
| `/site-map.xml` | 301 to `/sitemap.xml` |

## Authoritative source

Crawler assets are generated by the ebook derivative pipeline and validated in `config/crawler-checksums.json`. The canonical publication targets are `https://jonathan-harris.online/robots.txt`, `https://jonathan-harris.online/sitemap.xml` and `https://jonathan-harris.online/llms.txt`.

Do not create duplicate sitemap XML files for aliases. Update governed route data, regenerate, keep the compatibility redirects direct and rerun `python3 scripts/check_crawlers.py`.

Permissive `robots.txt` is necessary but not sufficient for crawler accessibility. Release verification should also confirm the deployed Cloudflare layer is not rejecting intended search/referral crawlers.


## Automatically updated R2 blog sitemap (19 November 2026)

The canonical `/sitemap.xml` is augmented at request time by `functions/sitemap.xml.js`.
Its governed, committed static sitemap remains the base. The function retains existing
dynamic route-manifest and podcast-RSS entries, and reads `blog/posts.json` directly
from the `BLOG_BUCKET` R2 binding. Every published manifest slug becomes a canonical
`/blog/posts/<slug>/` entry, with an optional `lastmod` derived from the post's
`updated_at` or `published_at`. This is the **same manifest** used by the public
blog index; there is no shadow article database, new scheduled task or deployment
required when weekly AIMS publishing adds or removes a post.

The sitemap response has a five-minute public cache (`max-age=300, s-maxage=300`).
After a successful weekly publish updates the R2 manifest, the next uncached sitemap
request includes the new article automatically; no PR or Pages rebuild is required.
The response reports `X-Blog-Sitemap-Source: r2` and
`X-Blog-Posts-In-Sitemap: <count>` for operational verification.

If the R2 binding is absent, the manifest cannot be read, or its format is invalid,
`/sitemap.xml` returns a retryable HTTP 503 with `Cache-Control: no-store`
instead of silently reporting a complete sitemap. The blog article paths continue
to render through their existing Pages Functions and original R2 objects.
The existing legacy sitemap aliases still redirect to the canonical path.
