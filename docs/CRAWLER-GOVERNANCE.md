# Crawler Asset Governance

## Canonical files

| Asset | Canonical path | Purpose |
|-------|---------------|---------|
| Robots | `/robots.txt` | Canonical robots directives, AI crawler allowances and sitemap pointer |
| Sitemap | `/sitemap.xml` | Canonical sitemap, referenced from robots.txt and published as the only root sitemap XML body |
| LLM index | `/llms.txt` | Human-readable crawler/retrieval index that complements normal crawlability |

## Compatibility aliases

Historical names remain compatible through direct permanent redirects or Pages Function routing. They are **not** duplicate physical sitemap bodies.

| Route | Behaviour |
| --- | --- |
| `/robot.txt` | 301 to `/robots.txt` |
| `/Sitemap.xml` | 301 to `/sitemap.xml` |
| `/site-map.xml` | 301 to `/sitemap.xml` |

## Authoritative source

Crawler assets are generated by the ebook derivative pipeline and validated in `config/crawler-checksums.json`. The canonical publication targets are `https://jonathan-harris.online/robots.txt`, `https://jonathan-harris.online/sitemap.xml` and `https://jonathan-harris.online/llms.txt`.

Do not create duplicate sitemap XML files for aliases. Update governed route data, regenerate, keep the compatibility redirects direct and rerun `python3 scripts/check_crawlers.py`.

Permissive `robots.txt` is necessary but not sufficient for crawler accessibility. Release verification should also confirm the deployed Cloudflare layer is not rejecting intended search/referral crawlers.
